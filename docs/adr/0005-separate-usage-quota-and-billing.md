# 0005 — Keep local token usage, subscription quota, and API billing separate

ccusage reads supported local agent records and supplies token counts and estimated costs, but those records cannot establish a subscription's remaining quota or an account's actual bill. We will keep ccusage as one local-log adapter and add independent adapters for provider quota polling, official billing/balance APIs, and per-request API usage receipts where available. Each reading must retain its account, agent when known, metric and unit, interval, observation time, source, and whether it is official, observed, or estimated. The local service merges readings only when their identities and units make aggregation valid; unavailable readings stay unavailable. In particular, a currency balance must never occupy a token field, a prompt count must never be labeled tokens, and estimated cost must never be labeled actual spend.

The service will poll quota endpoints on their own schedule and preserve the last successful sample with a freshness limit; the device's hourly pull does not trigger vendor polling. Request receipts can measure direct API token use, while an official bill or balance is a separate monetary reading. Local agent logs and request receipts may describe the same call, so the service must deduplicate by a stable request identity before adding them. When a source cannot expose an account-wide total, show its observed coverage instead of claiming completeness. This extends the local-service credential boundary from [ADR 0001](0001-usage-proxy-holds-credentials.md) and supersedes its suggestion that a balance API can supply token consumption.

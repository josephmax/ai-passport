# 语音输入可行性：麦克风挂坠与桌面输入

## 范围与结论

需求：跨平台桌面语音输入，优先 macOS。挂坠采集麦克风音频并发送三键动作；电脑接收音频、运行识别，把文字或映射后的导航／确认键输入当前应用。适合作为可选的独占模式实现。本文件是调研和实施建议；尚未实现语音固件或桌面接收程序，也未验证麦克风识别准确率及运行内存余量。

现有 ES8311／I2S 采集路径通过 `bsp_audio_read()` 支持 16 kHz、16-bit 单声道 PCM。ESP32-C3 的 USB 外设是固定功能 Serial/JTAG，不是可编程 USB Audio 或 HID。因此现有 USB 接口不能通过添加 TinyUSB 就变成标准 USB 麦克风／键盘。第一版采用 Wi-Fi 加桌面伴随程序；以后可增加带帧协议的 USB 串口通道，但须将二进制音频与控制台日志分离。蓝牙 LE 不是经典蓝牙耳机音频；同时保留 Wi-Fi 再增加 BLE HID 会增加无线与生命周期集成，也不能解决麦克风传输。

## 第一阶段建议

```text
挂坠：麦克风 + 按键事件
  -> 鉴权的局域网 WebSocket：二进制 PCM + 有长度限制的控制报文
  -> 桌面接收器：校验会话、缓冲音频、识别适配器
  -> whisper.cpp 推理进程（或 FunASR 适配器）
  -> 桌面输入桥：输入文字及映射按键
```

推理放在独立进程，避免模型加载和 CPU 工作阻塞 Token 服务。接收器须运行在被控制的电脑上，或转发给该电脑的输入桥；单独一台 NAS 不能把文字输入 Mac。第一版采用点击开始／点击停止，因为现有 BSP 暴露按下、单击、双击和长按，没有松开事件。按住说话须补上经过测试的松开事件，并抑制随后单击。三个按键共用 ADC 电阻梯，不依赖组合键。

仅在语音模式内生效的暂定可配置映射：

| 按键事件 | 默认动作 | 可配置替代 |
| --- | --- | --- |
| UP 单击 | 光标左移 | 上移、Home、上一项 |
| DOWN 单击 | 光标右移 | 下移、End、下一项 |
| 空闲时 OK 单击 | Enter | Tab、确认预览 |
| OK 长按 | 开始／停止录音 | 支持松开事件后改为按住说话 |
| UP 双击 | Backspace | Escape、取消预览 |
| DOWN 长按 | 退出语音模式 | 保留为设备本地动作 |

配置应从命名动作中选择，不执行任意 shell 命令。转写文字不隐含 Enter；回车始终是明确按键动作。录音开始时记录目标应用，输入前确认焦点未改变，否则保留结果等待确认。macOS 文字输入／按键事件需要辅助功能权限；Windows 和 Linux 使用平台适配器，Windows 高权限应用及 Wayland 需单独验收。第一版使用文字插入／粘贴和离散按键；包含组合文字与候选窗口的完整系统输入法属于更大的独立功能。

## 开源复用

| 项目 | 可复用能力 | 仍需完成的集成 |
| --- | --- | --- |
| [whisper.cpp](https://github.com/ggml-org/whisper.cpp) | 本地多语种识别、Apple 加速、HTTP 服务 | 接收 ESP PCM、生成推理请求、管理模型生命周期、输入桥 |
| [Handy](https://github.com/cjpais/Handy) | 跨平台离线语音输入、桌面粘贴与快捷键 | 文档中的 CLI 控制本地录音，不是有文档的 ESP PCM 接口。需扩展音频来源或参考其输入实现，并验证所选版本 |
| [FunASR](https://github.com/modelscope/FunASR) | 中文流式识别、标点、WebSocket 协议 | 选用流式模型与运行时，部署较重；模型权重许可证独立 |

建议先用电脑端多语种 Whisper small／base，停止录音后输出最终文字；中文不能选 `.en` 模型。如果实测中文准确率或交互延迟需要，再增加 FunASR 流式适配器。这些项目都不能直接当作完成的网络麦克风加三键输入设备。

## 开销与资源预算

以下传输数据是计算值，不是实测。16,000 samples/s × 2 bytes = **32,000 bytes/s**，即不含协议开销的 256 kbit/s、**每分钟 1.92 MB**。20 ms 帧为 640 bytes；16 KiB 队列约覆盖 512 ms。60 秒完整录音为 1.92 MB，无法放进此板 RAM，应由电脑缓冲整句。队列溢出或断线时明确报错并取消该句，不能悄悄丢音频或无限增加缓冲。主机先设可配置的 60 秒单句限制。

| 板端资源 | 建议预算／边界 |
| --- | --- |
| PCM 队列 | 固定 16 KiB |
| 采集／网络任务栈 | 初始合计 10–12 KiB，验证栈高水位 |
| 帧协议、控制队列、socket／codec 分配 | 计入剩余空间；新增活跃堆目标合计 **40–64 KiB**，暂定 |
| I2S DMA | BSP 已为每个通道创建六个 240-frame 描述符；实测分配量，不能只算 PCM 有效载荷 |
| 显示 | 沿用 9.6 KB 局部 DMA 缓冲和 24 KB LVGL 池；小型状态界面，不建全屏缓冲 |
| TLS | 现有产品规格预算握手峰值 40–50 KB；选 WSS 前实测，握手不与活跃流重叠 |
| Flash | ESP 不存识别模型；实现后测量固件增量 |

应用没有 PSRAM。本次未取得当前构建 map 或可信的实时最小空闲堆／最大连续块读数，因此 **40–64 KiB 是设计目标，不是已证明装得下**。进入语音模式须停止并确认音频播放退出，禁止音效任务在采集中暂停 codec，推迟素材下载和快照网络任务，把宠物停在静态帧，并在采集退出前禁止自动休眠。番茄计时／经验状态继续运行，其网络与音频副作用暂缓。现有 `app_audio_fx_stop()` 只设标记，播放循环目前未检查该标记；接入采集前须增加有界取消和音频所有权交接。

本地识别没有按分钟 API 费用。whisper.cpp 上游未量化模型内存表约为 base 388 MB、small 852 MB、medium 2.1 GB、large 3.9 GB；这些是参考模型占用，不是整个桌面进程内存或延迟承诺。量化可降低占用。具体模型 CPU／GPU 负载、中文质量和停说后延迟须在目标 Mac 上测试。云端 ASR 可选，第一阶段不引入。Wi-Fi 流传输及麦克风工作会增加功耗并阻止休眠；续航需结合流传输实测电流与电池容量，不能凭空估计。受限缓冲的麦克风模式暂不需要提出换板；全天常开 ASR、板上大型模型识别及同时素材同步不在第一阶段范围。

## 启用功能前的验收

1. 在现有固件记录空闲内部堆、历史最小空闲堆、最大内部连续块、DMA 堆和各任务栈；连接、录音、停止及返回主屏时重复测量，记录固件 Flash 大小。
2. 验证固定缓冲不随录音时长增长；慢接收端、溢出、Wi-Fi 断线、接收端退出、坏帧、取消和重复按键报文均不导致误按键。
3. 连续运行至少 30 分钟并执行 100 次开始／停止，保留宠物／番茄／设置状态。检查 codec 所有权、无重启／看门狗、无任务／缓冲泄漏、休眠前完全关闭流。
4. 测量中文、英文、混合技术词、正常距离与环境噪声的削波／噪声和转写错误率；使用同一组录音比较模型，测量语音结束到文字出现的延迟及活跃电流。
5. 验收 Mac 文本编辑器、浏览器输入、终端、焦点切换、剪贴板恢复和权限拒绝；之后分别验收 Windows、Linux。验证方向键／Enter／Backspace 及改配置，Enter 只在对应事件发生。
